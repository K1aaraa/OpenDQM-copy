# Development guide

## Architecture and routes

`app/layout.tsx` provides fonts, shared metadata, the keyboard skip link, Header, main landmark, and Footer. Route files compose sections; editable content shared by sections belongs in `data/`. `lib/` contains small utilities and validation. There is no Next.js API server in the exported deployment.

| URL               | Route                        | Main sections                                                |
| ----------------- | ---------------------------- | ------------------------------------------------------------ |
| `/`               | `app/page.tsx`               | Hero, mission, ecosystem partners, upcoming workshops        |
| `/about/`         | `app/about/page.tsx`         | Introduction, funding, team cards, Project Summary           |
| `/events/`        | `app/events/page.tsx`        | Upcoming workshops, past webinars, interview CTA             |
| `/events/[slug]/` | `app/events/[slug]/page.tsx` | Session information and expandable presenter profiles        |
| `/resources/`     | `app/resources/page.tsx`     | Research participation CTA; survey is also in the navigation |
| `/contact/`       | `app/contact/page.tsx`       | Email and expandable interview form                          |
| `/updates/`       | `app/updates/page.tsx`       | Reserved page; intentionally absent from navigation          |

Webinar routes are generated by `generateStaticParams`; a new webinar needs a unique slug in `data/webinars.ts`. Presenter records are grouped by session in `data/webinar-presenters.ts`. Source Teams URLs are retained in the data for verification, while the visible video control remains disabled until a video is available. Use verified profile links; do not invent biographies where the source has none. Profiles without biography text still expand to show their links.

## Styling and accessibility

The project uses Poppins, CSS variables, and plain CSS. `app/globals.css` contains shared tokens, navigation, typography, common sections, forms, footer, and responsive rules. `styles/project-summary.css` and `styles/webinars.css` own their specific page sections. The layout imports these after the shared styles. Search by component class name before adding CSS; update an existing rule rather than adding a competing override.

Keep `--night`, `--grape`, `--muted`, `--gradient-brand`, `--radius`, and spacing conventions consistent. Header and footer branding is text-only. Partner and funding logos are separate content and remain visible. Do not reintroduce the retired OpenDQM logo or logo favicon.

Use semantic headings, labeled form controls, visible keyboard focus, and `prefers-reduced-motion`. Presenter biographies use native `details/summary`, requiring no state management. Team cards have front/back controls and restore keyboard focus. The mobile menu confines focus, closes on Escape or navigation, and makes the background inert while open.

The page must work at 320px without relying on `overflow-x: hidden` to conceal clipped content. Grid/flex children with long text need `min-width: 0`. Check mobile, tablet, and desktop when changing typography or columns. Hover effects must not be the only way to reach information.

## Documents and images

The Project Summary is `public/documents/OpenDQM summary.pdf`; its page preview is `public/documents/opendqm-summary-preview.png`. When replacing the PDF, also regenerate the preview and update its image dimensions and description in `app/about/page.tsx` if needed. The preview and View PDF button open the same document in a new tab. The proposal PDF is retained as a separate source document in the document register.

Public file URLs use `assetPath()` from `lib/assets.ts`. Encode spaces in PDF URLs. Next.js `Link` handles internal route prefixes automatically; do not manually prefix those. Linux and GitHub Pages are case sensitive, so image paths must match filenames exactly. Optimized WebP team photographs live only in `public/images/team/`; avoid duplicate copies at the image root.

## Interview form

`ContactChoices` expands the form for `/contact/#schedule-interview`. `InterviewForm` validates required fields and sends through one selected external transport. Endpoint precedence is Apps Script, then email, then Worker. These public endpoint settings are embedded at build time; restarting development or rebuilding a deployment is required after changes.

`lib/interview.ts` owns field validation, size limits, timezone checks, and spreadsheet-safe text. `lib/appsScript.ts` submits to a Google response iframe and checks its acknowledgement nonce and origin. Success must mean an acknowledged write; failures preserve entered values. Never test with real personal information. See `integration/README.md` for the independent backend setup.

## Tests and debugging

- `tests/*.test.ts`: content, timezone boundaries, validation, Worker responses, and Apps Script acknowledgements/writes.
- `tests/browser/site.spec.ts`: exported route loading and images at six widths, accessibility, mobile keyboard navigation, team and presenter controls, PDF content, and invalid interview input.
- `scripts/serve-export.mjs`: development-only static preview server with repository-prefix support.
- `scripts/prepare-export.mjs`: automatic `postbuild` normalization for Next 16.4 segment-prefetch filenames on Windows. The exporter currently preserves Windows separators inside these names; the client router expects dots. The script adds the expected files without editing dependencies. Linux exports are already flat and require no copies. Remove the workaround only after an upgraded Next build passes the no-failed-resource checks on Windows.

For a missing asset, first check filename case, `assetPath`, and the build prefix. For a form failure, inspect the selected transport, rebuild-time endpoint settings, network response, and backend configuration; a disabled submit button without an endpoint is expected. For CI formatting failures, run `npm run format` and then `npm run check`.

## Repository hygiene

Keep source files in the directories above. Generated screenshots and one-off investigation scripts belong in ignored `.qa/`, not the repository root. `.next/`, `out/`, `test-results/`, and `playwright-report/` are disposable build/test output. `research/` contains a separate Python research visualization, not part of the website build. Preserve research and integration source unless its owner confirms it is obsolete.

Unused prototypes and their commented-out imports/JSX were removed during cleanup. Use version control or the roadmap for future ideas rather than keeping dead components in the active source tree.
